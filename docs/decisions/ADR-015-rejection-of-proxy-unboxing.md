# ADR-015: Rejection of GetUnproxiedType() — Proxy Awareness Belongs to Infrastructure

**Date:** 2026-08-11
**Status:** Accepted
**Deciders:** Erickson Lopez
**Context:** FINDING-002 from architectural audit — `GetUnproxiedType()` introduced Castle DynamicProxy awareness into the domain layer.

---

## Context

`Entity<TId>` historically contained a `protected virtual Type GetUnproxiedType()` method:

```csharp
protected virtual Type GetUnproxiedType()
{
    var type = GetType();
    if (type.ToString().StartsWith("Castle.Proxies.", StringComparison.Ordinal))
        return type.BaseType!;
    return type;
}
```

This method was used in `Equals()` and `GetHashCode()` to ensure that a Castle DynamicProxy wrapper (commonly generated by EF Core lazy loading or NHibernate) would compare as equal to its underlying entity instance.

## Problem

1. **Domain Purity Violation:** Castle DynamicProxy is an ORM infrastructure concern. Its presence as conceptual knowledge in the SharedKernel domain layer violates the fundamental DDD boundary: domain should not know about infrastructure. This is the most critical issue.

2. **String Allocation in Hot Path:** `type.ToString()` generates a heap-allocated string on every `Equals()` call. In high-throughput scenarios (sorting, grouping, HashSet operations), this means unbounded allocations in what should be a zero-allocation equality path.

3. **Incorrect OCP Application:** The method was `virtual`, theoretically allowing subclasses to override "what type am I for equality purposes." This is a misapplication of the Open/Closed Principle — there is no legitimate domain reason for an entity to disguise its own runtime type.

4. **Invisible Coupling:** The coupling to Castle is not visible in the package dependency graph (no `PackageReference` to Castle). This is the worst form of coupling — conceptual coupling without explicit declaration.

5. **HashCode Contract Risk:** If `GetUnproxiedType()` returned a different type for proxied vs real entities, but was not symmetric, `HashCode.Combine(type, id)` could produce different hash codes for equal entities, breaking `HashSet<T>` and `Dictionary<TKey,TValue>`.

## Decision

**Remove `GetUnproxiedType()` entirely.** Use `GetType()` directly in `Equals()` and `GetHashCode()`.

```csharp
// Before (WRONG — infrastructure contamination, string allocation):
if (other is null || other.GetUnproxiedType() != GetUnproxiedType())

// After (CORRECT — direct, AOT-safe, zero-allocation):
if (other is null || other.GetType() != GetType())
```

## Consequences

### Positive
- Domain Purity restored — no conceptual knowledge of ORM proxies in the domain layer.
- `Equals()` path becomes allocation-free (no `type.ToString()`).
- Removes the `virtual` extension point that had no valid domain use case.
- `HashCode.Combine(GetType(), id)` is symmetric and deterministic.

### Negative
- **BREAKING:** If consumers were using EF Core lazy loading proxies and relying on proxy-transparent equality (entity == its proxy), this behavior changes. Two objects of different runtime types will no longer be considered equal, even if they represent the same entity.

### Migration for ORM Proxy Users

If consumers need proxy-transparent equality (e.g., EF Core lazy loading), the solution belongs in the **Infrastructure layer**, not in the SharedKernel:

```csharp
// Option A: Disable lazy loading proxies (recommended for DDD):
services.AddDbContext<MyContext>(opts => opts
    .UseSqlServer(conn)
    .UseQueryTrackingBehavior(QueryTrackingBehavior.NoTracking));

// Option B: Custom IEqualityComparer in the repository/Unit of Work:
public class EntityEqualityComparer<TId> : IEqualityComparer<Entity<TId>>
    where TId : notnull, IEquatable<TId>
{
    public bool Equals(Entity<TId>? x, Entity<TId>? y)
    {
        if (x is null && y is null) return true;
        if (x is null || y is null) return false;
        var xType = x.GetType().BaseType ?? x.GetType(); // unwrap proxy
        var yType = y.GetType().BaseType ?? y.GetType();
        return xType == yType && x.Id.Equals(y.Id);
    }
    // GetHashCode similarly...
}
```
